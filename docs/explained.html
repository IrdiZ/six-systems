The problem

Hospitals store every scan, result and report as a file for a person to read. Little of it arrives as data that a computer can use.

A result may be a photo of a screen, a fax or a PDF. Other results arrive with local codes, other units or no patient number.

We cannot use real patient data. This simulation uses 11 sending systems and 40 patients to measure the gap.

One patient's week

The numbers

The percentages reflect how this simulation was built. They show the mechanism, not a measured rate at any hospital.

The simulator writes the true values to a hidden answer key that the assembler never sees. The score counts how many true values survive in the assembled data.

Every true fact ends with one of four statuses.

The question

The gap shows up in two places, and each has a different owner.

Care between organisations. Results from a neighbouring hospital or regional lab arrive with different codes and units, sometimes without a patient number, sometimes by fax. Doctors re-type, re-check or miss them. The Dutch exchange law (the Wegiz) is in force. Its rules for exchanging the patient summary now follow the dates of the EU's European Health Data Space (EHDS): patient summaries by 2029, lab results and images by 2031.

Research and AI. Researchers need thousands of cases as data. Key measurements sit inside images and PDFs, scanners discard raw data, and every study repeats the same manual export. European rules (the EHDS) are starting to require that this reuse is possible.

The prototype asks one question: which of the two problems costs more in practice? The answer decides what to build next.

Limits

  • All data is synthetic. Every person, value and organisation is invented. BSNs pass the 11-proof check but belong to no one.
  • The percentages follow from the simulation settings. We chose how often results are faxed or lack a BSN.
  • Not a medical device and not a product.
  • Formats are realistic in shape and simplified in detail.
  • OCR readings are pinned. A reference file stores the readings of the reference build for each image, so every machine assembles the same case.
  • OCR has clean input here. The echo screen captures use clean fonts and real captures are messier, so real recovery would be lower. Even here, Tesseract misreads "cm" as "¢m" and fails on some values.
  • The model shows the shape of the problem. It uses public information about a typical Dutch academic hospital, not the real data flows of any hospital.

Glossary

Archive
The system where hospitals store scans, reports and other files. PACS is the image part. It is built for viewing, not for extracting data.
Provenance
The record of where a value came from and what happened to it on the way.
HL7v2
A message standard from the 1990s that most hospital systems still use to send results.
EDIFACT
An older message format. Dutch labs use a variant called MEDLAB to send results to GPs.
LOINC
An international code system for lab tests and other observations.
DICOM
The standard file format for medical images.
Secondary Capture
A DICOM file that holds a picture of a screen, for example the measurement panel of an ultrasound machine.
DICOM SR
Structured Report: measurements stored as data. Newer echo machines can write one.
BSN
The Dutch citizen service number. Care providers use it to identify a patient. Some files arrive without it.
OCR
Software that reads text out of an image. It makes mistakes: here it read "cm" as "¢m".
Pseudonymise
Replace identity with a code. Records stay linkable for research and nobody can tell who they belong to.
EHDS
The European Health Data Space: EU rules for the exchange and reuse of health data.
